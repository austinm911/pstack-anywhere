## Accepted upstream behavior

- **Evidence labels.** poteto-mode requires every claim to carry its evidence or a measured, inferred, or guess label (#341).
- **Full-autonomy calls.** poteto-mode decides calls a full-autonomy grant covers, applies and explains defaults for operator-only calls, and still pauses on named gates.
- **Round-based verification.** Autopilot-full, autopilot-stack, and multi-phase-plan verify each round from the code-ready head instead of only the merge-ready head. The rebase policy keeps the merge base through fix rounds. Audits run as two or more focused lanes. Proven findings return in one fix-forward with a red test or repro receipt. Stuck-agent tracking uses a per-owner `children.tsv`. Countersigned approvals are recorded without bypassing forge-enforced approvals.
- **Quieter ticks.** The multi-phase tick prompt reports only new tracked changes and logs every tick.
- **Patch-id noise rule.** Shipping keeps a lane result when the patch differs only in tests, docs, or lint config and a double build proves the differences are noise.
- **Swarm briefs.** Verification and measurement briefs name exact SHAs and method. Workers list every provable issue. Results missing them are rerun once, then recorded as a gap.
- **Operator-neutral pronouns** (#362) in the autopilot and multi-phase playbooks.
- **Model defaults** (#365, #414). Bug-fix, perf-issue, and hillclimb delegate to the fast code model instead of the strongest judgment model. Review panels shrink from four entries to three. The port states defaults as role slots, so only the role names changed. Interrogate drops Reviewer D.
- **Reasoning budget** (#366). setup-pstack-anywhere asks for `unlimited`, `large`, `medium`, or `small`, records a `# budget` line, and rewrites the effort of model values that carry one.
- **Trimmed prose.** Upstream removed restated guidance from blast-radius, figure-it-out, feature, pause-safely, prove-it-works, sequence-verifiable-units, show-me-your-work, tdd, technical-writing, and unslop. Accepted as upstream judgment.
- **log.sh.** The header is written when the log is missing or empty, and always by append. Exercised on a new file, an existing file, and an empty file. Each produced exactly one header and every row.

## Portability adaptations

Conflicted blocks were reset to the port side, then each upstream semantic change was re-applied in port vocabulary:

- Cursor cloud agent → `spawn_worker` owner. Bugbot → `review_automation` with the human-comment fallback. `/deslop` → `slop_strip` with the unslop fallback. Control skills from `cursor-team-kit` → `cli_driver` or `ui_driver`, with the existing `type-check-only` stop when the driver is absent.
- `/loop` and cloud-sleeper ticks → `wake_on_event`. `git show origin/main:pstack/...` re-reads → sibling skill addressing (`trunk_reread`). `AskQuestion` → `human_question`. Bot-comment sweep → review-comment sweep.
- Model slugs stay out of skill text. `coupling.yaml` `model_roles.was` now records the 0.15.3 slugs.
- The budget step is generalized from Cursor's slug effort tokens to any identifier that encodes effort, including pi's `:level` suffix. Aliases and identifiers without an effort are unchanged. When nothing carries an effort, the skill says the budget changes no role. The port's `auto` defaults mean a fresh setup records a budget without changing any role.
- `check-plan.mjs` keeps the port's slug-agnostic `LANES` regex.
- The upstream README note that pre-0.15.3 rule files pin old models does not apply. The port's defaults are `auto` and role slots.

No new capability axis was needed. Every new instruction resolves through an existing axis or is harness-neutral (`children.tsv`, the agent list "where the platform has one", AGENTS.md pre-review checks).
